# nadav-design · mode `redesign`

## Mode `redesign` (the whole app: the direction as a standalone demo, one review round, a tag, a build plan; no app code)

Part of the nadav-design skill. Before this file read the Hard rules of `SKILL.md`, then `shared/rules.md`
and `shared/platform.md`. Every path here is relative to the skill folder, one level above this file.


Read `redesign/README.md` (in the skill folder) before step 0 and follow it step by step: it holds the procedure, the tools (`redesign/tools/`), the templates and the workflow scripts. Generalized from the SporChat v4 redesign (22.9–11.10.2026). This mode never writes into the app repo (not even `.omc/`): the demo, the decisions, the debts, the run log and the build plan live in an output repo of its own, and the build session that START-BUILD opens after Nadav approved the plan takes every screen through `screen`'s gates.

For an app this mode's page carries the direction, not every screen: the design language, the inventory, the main journey as one playable flow, the shared components and design values, and the decisions. It gets one review round with Nadav, is tagged and frozen when he approves the direction, and the build plan's first unit is the app's own preview on invented data, where the build session designs every other screen and state under `screen`'s gates and shows each one to him playing (`shared/rules.md`, «An app is built once»: the why, and the runs it does not cover, such as SportChat v4's running build and MediZen's unapproved demo, which finishes its own rounds and is tagged at approval).

0. **Preconditions and scale.** Declare the tempo and the track. Read the app (routes, components, states, DESIGN.md/PRODUCT.md when present, users), count screens, size the run (README «Scale»). Pin the app's commit. Output folder outside the repo and outside `/tmp` (`~/design-redesign/<app>/`), its own git repo, set up as README step 0 lists. Evidence: the app's commit, the counts, the sizing, `git log -1`.
1. **Design language.** BRIEF.md from the app's own character, on DESIGN.md/PRODUCT.md when they exist; never another app's look or the generic Impeccable look, never `craft`/`bolder`/`overdrive`. Nadav approves (AskUserQuestion, recommendation first). Evidence: the approved BRIEF.md and two or three phones in it.
2. **Inventory.** INVENTORY.md (every screen, state and control today), STORY.md (the main journey), today's look from the sources README step 2 lists in order (a screen none can capture is drawn as «היום · לא צולם»). Evidence: the files and `ls today/`.
3. **Direction demo.** Shared components from BRIEF.md first, then the main journey of STORY.md as one playable flow (`proto/index.html`), with a section per screen the journey passes through: «היום», «אחרי», a «מצב» phone per state the journey meets; dark, light and 320; RTL-first, real copy, 44px, 4.5:1, local files only. Screens and states off the journey are not drawn here; they are designed in the app's preview after the tag. `tools/build.py`, `tools/shoot.mjs`. Evidence: the prototype link, the build line and clean reports.
4. **Questions.** DECISIONS-OPEN.md, asked in AskUserQuestion batches of up to 4, recommendation first; answers numbered in DECISIONS-ANSWERED.md, never re-decided.
5. **New features.** On the journey, «חדש · מאושר» or «מוצע · <date> · אחרי הליבה · <title>» phones with the note under the phone; off the journey, a FEATURES-PROPOSED.md row only, designed later in the app's preview. Every row is carried into the plan.
6. **One review round, then the tag.** Fix lanes by screen group with cross-lane requests, rebuild, fresh Opus verify by lenses (craft, words and sources, the STORY), ONE full sweep then targeted confirms that account for every finding id (≤3). Green only when all of it holds (README «Green means all of it»). Then Nadav answers keep/change/revert on CHANGES-<date>.md; his change and revert answers are applied by a fix run of the same round, and he approves the direction (AskUserQuestion). The approved commit is tagged and the page is read-only from then on: a later design change goes to the plan and is made in the app's preview, never in another round here. If he does not approve the direction, ask him how to go on; a second round is never started on its own. `redesign/workflows/demo-round.js` only when Nadav opted into multi-agent orchestration; otherwise subagents one by one, with the model `rules/model-routing.md` names for the role. Evidence: the round's `gates`, his answers, the tag.
7. **History.** `pre/` before every edit, `after/` shots, a dated changelog line per change, CHANGES-<date>.md in plain Hebrew per round.
8. **Build plan.** It names the approved tag. Unit 1 is the app's preview on invented data with the check that keeps demo code and invented data out of production, then tokens and shared components, then the screens: one the tagged demo drew cites its column labels, one it did not draw cites its INVENTORY.md row and is designed in the preview. Units cite column labels, `tools/check-anchors.py` 0 missing and 0 wrong; fresh Opus review to APPROVE, then a diff-only confirm, then the second model (`rules/working-style.md`, "Second model"; `omc ask codex` on the config default, never `-m`); every later edit diff-confirmed; START-BUILD prompt and checklist (`redesign/workflows/plan-review.js`). Then Nadav approves the finished plan (AskUserQuestion); reviewers approving is not him approving. Evidence: the verdicts, which second model ran, his numbered answer.
9. **Partners** (only when Nadav asks): a partner page and guide; README points to the SporChat example.
10. **Ship.** Commit the output repo, publish the demo (claude.ai artifact or Nadav's own domain, never `*.vercel.app`), report with links, and end like every mode (checklist in the output repo's `RUN-LOG.md`, gap scan, `הבא:`).

README «Operating lessons» gives each rule its why: `model: 'opus'` on every `agent()`; big data in files, never in workflow args; one browser at a time after `uptime`; a checkpoint commit per phase; restart at `spec` from the extracted state (`tools/journal-state.py`) instead of resuming past a failed agent; a reviewer is never the author; gates read structured fields, never prose.
