# nadav-design · mode `retro`

## Mode `retro` (after a run; improves this skill, never the project)

Part of the nadav-design skill. Before this file read the Hard rules of `SKILL.md`, then `shared/rules.md`
and `shared/platform.md`. Every path here is relative to the skill folder, one level above this file.


0. Declare the tempo and the track. Find the run: the newest `.omc/design-runs/*.md` when present (untracked; absent on a fresh clone or worktree, then reconstruct from `git log` and ask Nadav to paste the checklist); for a `redesign` run, its output repo's `~/design-redesign/*/RUN-LOG.md` instead, because that mode never writes into the app repo; plus `git log --since` its date, `reports/dod/dod.json`, `.lighthouseci/` or the Lighthouse CI output, `docs/ui-audit/`, `.omc/notepad.md`. Evidence: the list of sources found.
1. **Step audit.** For every step of the mode that ran, one row: done with evidence / done without evidence / batched with another step / skipped / failed, with the line that proves it. "Done without evidence" and "batched" are failures of this skill, not of the project.
2. **Threshold audit.** DoD, axe, Lighthouse, `lint:ui`: met or not, and whether any threshold was lowered. Compare only the numbers, because setup legitimately edits routes, ports and reporters: the `minScore` / `maxNumericValue` lines of the project's `lighthouserc.json` against the template's, `--max-warnings=0` still in `lint:ui`, and the score gate line present in `.github/workflows/ui.yml`. Any difference is a P0 finding.
  `e2e/dod/dod-shared.ts` is compared by **meaning, never by bytes**: any repo with a formatter rewrites its quotes on the first commit, so "byte-identical" is a test that fails on every project for a reason that matters to nobody, and it therefore stops being read. Diff it, then classify each hunk: formatting (ignore), something the template gained that the project lacks (**port it back into the project and say so**), something the project gained that the template lacks (**port it up into `~/nadavai/templates/` in step 6**). Green Room was three template improvements behind and one ahead, and the byte rule had flagged it as a single undifferentiated P0 that said nothing about which way to move.
2b. **What Nadav caught, against the gates.** `node redesign/tools/owner-catches.mjs <project>/docs/ui-audit/MEASURES.md` (during a redesign, the output repo's `MEASURES.md`): per period and class, what the gates caught before ship, what Nadav caught before ship, what was found after ship, and the share the gates caught; the escapes by the gate that should have caught them, and those in a class no gate covers. The tool prints, with the share, what it may and may not be read as; that text goes into the retro's report with the number. A class where Nadav caught more than the gates, or a gate that keeps missing, is a finding for step 5(b). Then the cross-check, so a catch with no row does not raise the share unseen: Nadav's own messages in the run's sessions (the user messages of the run's session transcripts, the `.jsonl` files of the project's folder under the Claude projects directory, read locally and for the run's dates only), and in a `redesign` run every «לשנות» or «להחזיר» answer in its `CHANGES-<date>.md` files and every `DECISIONS-ANSWERED.md` row that rejects something on a screen: each one that names a problem on a screen and matches no `owner` row (by date and `ref`) is listed. When any row is malformed or sits outside the table (no leading `|`, or after a blank line), the tool withholds every share and exits 1: the report gives the counts of the rows read, says the share is withheld and why, and gives no number in its place. Those, the malformed rows, the rows outside the table and the repeats go into step 5(a), for the next run in the project to add or correct (this mode writes nothing into the project). In the `Tasks` table, a task whose `after` share `completed` is lower than its latest `baseline` is a finding too (`ship` step 8b). Evidence: the tool's output and the cross-check list.
3. **Tool audit.** Every skill, plugin, template or command that was missing, errored, needed a permission prompt, was outdated (`npx` version vs plugin version) or produced output that was not used. Time per step when known.
4. **Question audit.** Questions asked that the repo already answered (breaks Nadav's rule), and decisions taken silently that should have been asked.
4b. **The gap scan** (`SKILL.md`, «The gap scan»): retro proposes it without being asked, like every mode.
4c. **Tool freshness.** `claude plugin marketplace update` + `claude plugin list --outdated` (or the equivalent), `npm view` on `eslint-plugin-tailwind-rtl`, `@argos-ci/playwright`, `@axe-core/playwright`, **`axe-core` itself**, `@playwright/test`, `@lhci/cli`, `impeccable` vs what the project and the templates pin — and read the INSTALLED version, not the range: `axe-core` is a transitive dependency, a caret range happily sits two minors behind in a lockfile, and it is the package that decides which rules exist. Green Room's `axe = 0` was measured on 4.11.4 while 4.13.0 had shipped `aria-tab-name` (WCAG 2 A); new open issues on shadcn RTL (#10274, #8454, #9519, #9233) that changed status. Propose upgrades, never apply them here.
5. **Proposals.** Two lists. (a) For Nadav: what he forgot or has not run yet (from 4b), as commands. (b) For the skill: concrete edits, each tied to a finding above: to `SKILL.md` (a rule every mode needs) or `modes/<mode>.md` (a step of one mode), the `ux-*` wrappers, `~/nadavai/templates/*`, `~/nadavai/rules/*`, or the memory file. Say what stays as is and why. Show the list and stop for Nadav's approval. Nothing in the project is touched in this mode.
6. **Apply (after approval).** Edit in `~/nadavai` (the source of truth), run the `skill-creator` skill's review on the changed SKILL.md or mode file when a mode misfired or did not trigger, and always its `quick_validate.py` on every changed skill (frontmatter values with a colon must be quoted; its "Unexpected key argument-hint" message is expected, Claude Code supports that key), commit with Conventional Commits, push, `~/nadavai/update.sh`, and add one line with the lesson to the memory file `ui-ux-setup-prompt.md`. If the retro found a project-specific repeatable workflow, capture it as a project skill under `.claude/skills/`. Evidence: the diff, the commit, the update.sh tail.
