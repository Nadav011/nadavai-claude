# Native bar: what every Capacitor store app must have

Nadav, 2026-11-09: every store app stays Capacitor (no Expo, Swift or Kotlin rewrite), and gets every
native component and capability that a person can feel, end to end. This file is the bar. Each app
keeps a ledger `native/NATIVE-BAR.md` (or the repo's plan folder) with one row per item below, per
platform: pass, fail with owner and date, or "n/a" with the reason. A store build is not submitted
while a row that applies is "fail" without an owner.

Default is everything (Nadav, 2026-11-12: "always strive to do everything, at the highest level, end
to end"). Every row applies to every app. "n/a" is valid only for a fact about the app (a customer app
holds no owner, staff or money data, so no biometric lock; an iPhone-only build has no iPad layout),
never for "deferred", "later" or "not needed for now". A row that needs a product decision (what a
push says, whether the tab bar changes the look) is asked once while the plan is written, with the
full option first and recommended, so the first store build already carries it. Holding rows 3 and 9 back on MediZen, RetroBarber
and Cash (2026-11-10) cost each a second store version.

Plugin choice: official `@capacitor/*` first, then Capawesome or capacitor-community, then others.
Before adding any third-party plugin check: a release in the last 6 months, Capacitor 8 support in its
README, a free licence (Capawesome "Insiders" plugins are paid: money is asked first), and its
socket.dev page has no alert. Bundled apps: every plugin is a native change (store build, `builds.md`).

## A real 100: the native-feel score

Nadav, 2026-11-14: every store app reaches 100 on "feels like a real native app", a real score and not a claimed one, UI and UX included, with every native capability. The bar above is the checklist; the score measures it.

- Score six areas out of 100: A shell (launch, bars, safe areas, keyboard, back, links, updates, offline) 20; B native components (tab and nav bar, dialogs, sheets, menus, pickers, toasts) 20; C touch feel of the screens (transitions, scroll, refresh, press, selection, haptics, loading) 25; D device capabilities used 15; E system settings (text size, dark mode, motion, screen readers) 10; F proven on phones 10.
- The scorer is never the author: an independent model reads the code and the ledger and scores each area with evidence (file:line, a screenshot, a recording), and lists the gaps ranked by how much a person feels them (therapy-flow-v2 `planning/native-apps-2026-11-06/NATIVE-FEEL-AUDIT-2026-11-14.md` is the worked example: 54 and 49 on the first read, with every gap that rows 21-28 now name).
- Run it at the plan (to size the work), before each store submission, and after the device checks. Record the score, its date and the scorer in the ledger.
- Area F caps the score: no app is 100 until every row that applies has been checked on a real iPhone and a real Android phone, signed in, with the store build (the TestFlight or Play internal build is enough for the check; the public listing for the final claim, `SKILL.md`). A code read alone stops at 90, and a report says which.
- Look changes among the fixes (sheets, transitions, a new tab) are shown to Nadav as a rough first version before they spread (`working-style.md`, Requests); where a design spec exists, the live app is built to it and the differences go to the spec's owner.
- Two bars, both reported, and "100" only when both hold: (1) this native-feel score, areas A-F, which is where UI and UX *of the native feel* are scored (sheets, transitions, touch, keyboard, Hebrew direction); (2) nadav-design's design gates, which apply to every app and are pass or fail, not a score (its SKILL.md, «Quality bar»: the DoD at 100 on every route, axe 0, Lighthouse 100, `lint:ui` 0; the experience standard `nadav-design/standard/experience.md` is checked by its own reviewer, not scored here). The ledger records the native score (with its date and scorer) and the state of each design gate; a report reads "native feel 92/100, design gates: DoD 100, axe 0, Lighthouse 100, lint:ui 0". Passing the design gates never raises areas B or C, and areas B and C never stand in for a design gate (Nadav, 2026-11-14, asked that the 100 cover UI and UX too).
- A web-only fix ships by OTA to the shells it fits; a fix that needs a plugin, a config key or a native file rides the next store build. When the native layer itself lives on an unreleased branch, the feel fixes ride that release rather than being built twice (Nadav, 2026-11-14, "הכול ב-1.3").

## Lessons per row (MediZen, RetroBarber and Cash, 2026-11-10 to 11-14)

- Every row, remote shell: the web layer reaches every installed shell at the same deploy, old ones included. Each native call is a silent no-op unless `Capacitor.isNativePlatform()` and `isPluginAvailable(<name>)` both hold, and a feature that is proven on one platform only is gated per platform on the web side (Cash `NATIVE_TAB_BAR_PLATFORMS = ["android"]`), because adding a platform later turns it on for every shell of that platform at once.
- Row 2 (Cash, three review rounds): a system alert cannot be taken down from the web, so (a) one at a time: a second ask while one is up gets the web sheet at once, never a stacked alert; (b) every opening carries its own abort signal, so a late answer from a closed or replaced opening runs nothing (a parent that closes the sheet by data would otherwise still run «כן»); (c) a small own plugin (`CashPresentation.shown()`: Android `!hasWindowFocus()`, iOS `presentedViewController`) tells whether the alert came on screen, checked 1 s after the native call (load the plugin module first, preload it when the shell qualifies, bound the load at 3 s); only "not shown" falls back to the web sheet, and a shell without that plugin gets web sheets only; `document.hasFocus()` stays true under an Android AlertDialog, so it cannot tell; (d) on iOS wait about 400 ms after one alert closes before presenting the next (UIKit drops a present during a dismissal); (e) the service-worker reload treats an open native alert like an open dialog. Keep web: confirms that carry money, a form, a list, a third action, or a spec's friction (a permanent delete whose only solid button is «ביטול»). iOS system alerts follow the app's localization, not the page: set `CFBundleDevelopmentRegion` he and add he to `CFBundleLocalizations` and the project's `knownRegions`, or alerts lay out left to right on Hebrew iPhones. `@capacitor/dialog` 8.0.1 adds the cancel button with `.default` style (no `.cancel` option).
- Row 3, iOS (Cash): `CAPBridgeViewController.loadView` sets `view = webView`, so a bar added to `view` lands on the window. Give the controller a container view in `capacitorDidLoad`, the WebView filling it and the bar pinned beside it; raise the bottom safe area through a `WKWebView` subclass that reports max(own inset, the part the bar covers), not `additionalSafeAreaInsets` (that also raises the bar's own inset, a layout loop). The colours stay in a JSON file checked against the design tokens by a test, where a colour-literal guard forbids hex in app source.
- Row 6: `@capacitor/keyboard` removes WKWebView's own keyboard handling when it loads; with resize `none` a page that measures the keyboard itself sees nothing. Resize `native` shrinks the WebView like Android Chrome's `interactive-widget=resizes-content`, so one mechanism acts.
- Bundle budgets: a CI budget that counts every chunk in disk blocks also counts the native-only lazy chunks (Cash +42 KB for dialog, action sheet, keyboard, tab bar); raise it with that reason written beside the limit.

- Row 4: on Android the back order is: close the top sheet (through its history entry), then an older dialog, then go back, then minimize on a tab root; a screen with no history goes to the home tab. In a remote shell the web listener ships with the web deploy, so the store build reaches phones only after that deploy.
- Row 5: Capacitor's SystemBars applies its style after StatusBar, and its `DEFAULT` follows the phone's mode, not the app's: set both explicitly, then let the web follow the app's own theme class (`dumpsys window` shows `LIGHT_STATUS_BARS`).
- Row 7: the launch colour lives in `capacitor.config.ts`, Android 12+ `windowSplashScreenBackground`, the window background behind the WebView and the bundled offline page; a mismatch is a flash. Draw the adaptive launcher icon with its monochrome themed layer by a script, inside the 66 dp safe circle.
- Row 9: a customer app gets push too, in addition to its WhatsApp messages, behind the same send gates and its own kill switch, built dark and switched on after the action-safety replay. A token is stored only for the signed-in user's own device, never found by phone number.
- Row 10: biometric lock applies to owner, staff and money apps; a customer-only app is n/a.
- Row 13: Play in-app update is part of the row, not optional.
- Row 15: `assetlinks.json` lists both the Play app-signing key and the upload key; an emulator install signed with the debug key never verifies, so verify on a Play install. Claiming every path (`/*`, broad intent filters) makes every route reachable from a link: see `shell-checklist.md` row 24 (no plan price or upgrade ask on any route, App Review 3.1.1).
- Row 17: a remote shell shows a bundled offline page on a transport failure (Android `WebViewClient.onReceivedError`, iOS `server.errorPath`).
- Row 21 (MediZen, 2026-11-14): (a) the shared dialog is the one place the sheet lives; every hand-built overlay that holds a form or a detail view (modal, drawer, side panel) moves onto it, keeping its own guard, so that the row's check (every form at 390 and 515 px is a sheet) holds; a yes/no confirm and an action menu stay on row 2's system alert or action sheet, and widths of 600 px and up keep their desktop look; (b) the unsaved-changes question needs a mode for a dialog that already asks in its own `onOpenChange` (MediZen named it `own`) so the primitive does not ask twice, and one for a dialog that asked on desktop too (`always`); a design spec's own names win; (c) a dialog never closes while its save or charge is in flight, by any path: drag, Back, Escape, the X, the scrim; a failed save or charge leaves the sheet open with the error and the typed input; (d) a parent that renders `open={true}` and unmounts the dialog to close it skips the exit motion unless the primitive keeps an exit copy: check the exit on the device recording too; (e) a screen that pushed its own history entry for an overlay (the calendar did) doubles Back once the primitive adds one: one entry per overlay, owned by the primitive; (f) every form with a main action gets a footer, so its title and main action can be pinned: count the forms and the footers; (g) under Tailwind 4 a JS plugin listed in package.json does nothing until the CSS loads it (`@plugin`, or a `@config` file that lists it): `tailwindcss-animate` was installed but never loaded, so every `animate-in` class in 14 files was a no-op, on dialogs and on screens alike; (h) a stubbed `visualViewport` proves the layout math, not the keyboard: the row is checked on a phone.
- Row 22 (MediZen, 2026-11-14): with React Router 7, one wrapper of `router.navigate` per router adds `viewTransition: true`, which reaches every `Link`, `useNavigate` and `<Navigate>`, and the router re-applies it on POP. The wrapper also decides the motion and writes it to one attribute on `<html>` that the CSS reads: push, back, or cut, where cut (no animation) is a switch between tab roots or a tap on the tab bar, a replace, a change of the query only, `prefers-reduced-motion`, an iOS edge swipe (the WebView already animated it; told apart by the time since the app's own back call), and a POP the wrapper did not start. The row's check then covers each cut case too, not only push and back. React's own `<ViewTransition>` component (the `vercel-react-view-transitions` skill) needs react 19.3 or newer, per that skill's upstream as of 14.11.2026; on 19.2 the router path above is the way.
- Row 28, push for a reminder (MediZen, 2026-11-14, five review rounds): behind a kill switch that reads a missing row as off and is read again right before each send; quiet hours (22:00-07:00 in the business's time zone, MediZen: Israel) hold a push until 07:00, and drop it if its appointment starts first; no catch-up burst when the switch turns on or a phone registers: only what fell due within the last tick plus a margin goes; the person's "off" preference is read at send time; a failed push is retried while the reminder is still due, at most 3 attempts in all, then closed for good; a send the provider never answers stops the run there: it counts as failed, and the pushes after it wait for the next tick without counting an attempt (a token refused by Google stops the run the same way, since it fails for every push); a configuration refusal of one person's devices (FCM `THIRD_PARTY_AUTH_ERROR`, such as an iPhone with no APNs key in Firebase) is that person's failed attempt: it turns the run red so it is seen, and the run goes on to the other people; none of these stops the reminder's email or WhatsApp; push rows stay out of reconciliation views built for messages. Before switch-on, a read-only replay over the last 7 days counts the pushes that would have gone out (reminders, devices, night holds, the first run's sends), the reminder version of `rules/action-safety.md`'s replay.
- Row 19: start the Android emulator with `-gpu host`, not swiftshader (about 45% less CPU, and swiftshader alone makes most frames janky); compare the web list against a native Settings list on the same emulator for a ratio, and take absolute numbers on a phone.
- Row 20: names come from Chromium's computed tree (CDP `Accessibility.getFullAXTree`) next to `uiautomator dump`. Fixes that recur: the focused route heading draws no focus ring (`[data-route-focus]:focus-visible { outline: none }`), the toast region has a Hebrew name, every horizontal scroller Chrome makes focusable is a `role="group"` named by its section heading.
- R8 (with Play's DEX rule): keep line numbers, `shell-checklist.md` row 25. `testReleaseUnitTest` runs on the classes before R8, so it proves nothing about the minified app: install the minified release (signed with the debug key is fine), cold start it, read logcat for ClassNotFound/NoSuchMethod, and call every plugin once over the WebView DevTools socket. Code that reaches Capacitor internals by reflection (Cash's `DemoOriginBridge` reads `Bridge.getJSInjector()` and `JSInjector.getScriptString()`) needs an exact `-keep` per member. `shrinkResources` strips resources named only from the Capacitor config or looked up by name (shortcut icons, `splash`): list them in `res/raw/keep.xml`.
