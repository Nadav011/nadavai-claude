# Shell setup checklist

One row per item. Each row has a check that decides pass or fail. Rows marked "bundled" apply
only to the OTA model. Generic how-to is in the Capacitor skills listed in this skill's SKILL.md (app icons in
`capacitor-app-development`, splash in `capacitor-splash-screen`, deep-link files in
`capacitor-deep-linking`, plugin install in `capacitor-plugins`, safe areas in
`safe-area-handling`, keyboard in `capacitor-keyboard`).

| # | Item | Check | Why |
|---|---|---|---|
| 1 | App ids | Each app has one bundle id / package, equal to its existing listing (a TWA being replaced keeps its package and upload key). | A Play update of the same package and key replaces the TWA in place; a new package starts a new listing with no users. |
| 2 | Icons and splash | Generated from the brand mark by a script in the repo. The Android adaptive foreground fits the 66 dp safe circle. | Hand-edited assets drift from the brand and get cropped on round launchers. |
| 3 | iOS privacy manifest | `PrivacyInfo.xcprivacy` declares UserDefaults `CA92.1` and FileTimestamp `C617.1` (bundled), plus every collected data type of the App Privacy label. It parses with Python `plistlib`. | Live-update and Preferences keep state in UserDefaults and unzip bundles; a missing reason is an upload rejection. |
| 4 | Android manifest | `allowBackup="false"` when the app holds personal data; only the permissions used; `AD_ID` removed with `tools:node="remove"` when there are no ads; `POST_NOTIFICATIONS` when there is push. | Personal data must not go to cloud backup, and every permission is declared in Play's data safety form. |
| 5 | Push | FCM HTTP v1 on both platforms (APNs through FCM). The APNs auth key covers Production. The App ID has the push capability, so the profiles are regenerated. The payload carries no name, number or message text. `google-services.json` and `GoogleService-Info.plist` are gitignored, written at build time from the vault, and checked to belong to this app. | A sandbox-only APNs key cannot serve a store build, and a notification shows on a locked screen. |
| 6 | Deep links | Android: an `autoVerify` intent filter, and `assetlinks.json` lists the SHA-256 of the upload key and of the Play app-signing key. iOS: AASA plus associated domains (not built in the reference yet: MediZen's links are Android only, SHELLS.md section 6 item 4). The app routes only that exact origin. | Play re-signs with its own key: with only the upload key listed, links stop verifying once installed from Play. |
| 7 | Google sign-in | Android: one OAuth client per SHA-1 (upload key and Play signing). iOS: off unless Nadav decides, because a third-party login there needs an equivalent private option (Apple 4.8). | Without both Android clients sign-in fails on one of the two builds; on iOS it triggers Sign in with Apple. |
| 8 | Account deletion | Deletion can be started inside the app (Apple 5.1.1(v)), and a web path works signed out (Play's deletion URL). The exact behaviour, including legal retention of bookkeeping records, is approved by Nadav before it goes live. | Both stores reject without it, and deletion is an approval gate. |
| 9 | Reviewer login | When a reviewer cannot sign in as a customer (phone OTP, no local number), there is one fixed test account behind a kill switch. Its code is in the vault only, nothing is ever sent to its number, and the switch is ON only while a review is pending. Reference: therapy-flow-v2 REVIEWER-LOGIN.md. | Reviewers reject what they cannot sign in to, and a fixed code is an auth change (approval gate) that must not stay open. |
| 10 | Analytics in a second app | When one source builds two apps, follow the PostHog lines in `rules/working-style.md`. | A customer bundle must not carry the owner app's analytics. |
| 11 | Plugins per app | Each app lists its plugins explicitly (`includePlugins`), so push, Firebase or Google SDKs of one app never enter another built from the same source. | Every SDK in a binary is declared in its privacy forms. |
| 12 | Bundled: review-sensitive routes | On native, purchase and plan pages redirect away, and no remote `server` is in the config. A bundle check (therapy-flow-v2 `scripts/appstore/verify-native-bundle.mjs`) runs on the packaged web root. | Apple 3.1.1: digital goods bought outside in-app purchase are rejected. |
| 13 | Bundled: clean sync | `cap sync` leaves no tracked change, and `cordova.accessOrigins: []` keeps `<access origin="*" />` out of `config.xml`. | A sync that edits tracked native files changes the fingerprint between the build and its check. |
| 14 | iOS usage strings | Every capability the web layer reaches has its `Info.plist` string: `NSCameraUsageDescription` for `<input capture>` or a camera plugin, `NSPhotoLibraryUsageDescription` for a photo picker, location, microphone. Grep the web code for `capture`, `getUserMedia`, `geolocation`. | iOS kills the app the moment it asks without the string (found missing in CashControl, 2026-11-09). |
| 15 | Forced-update gate in an Expo app | The gate reads a server minimum and acts only when it is non-null and plausible for the platform; any error opens the app. | A fail-closed version check locks every user out on one database error. |
| 16 | Apple build gates | The build is made with Xcode 26 or later and the iOS 26 SDK (required for uploads since 2026-04-28); the deployment target is iOS 13 or later (since 2026-09-09); the updated age-rating questions are answered in App Store Connect. | Apple refuses the upload, or blocks the next update submission, when one is missing. |
| 17 | UIScene lifecycle (Capacitor 8.5+) | `npm i -D @capacitor/cli@latest && npx cap migrate` adds `SceneDelegate.swift`, the `UIApplicationSceneManifest` in `Info.plist` and the AppDelegate hook; a project not shaped like the template gets the manual steps of the 8.5 update guide. Then re-run the cold and warm start link matrix (row 6, `native-bar.md` rows 9 and 15). | Apple TN3187: in the next major release after iOS 26, an app built with the latest SDK without the scene lifecycle will not launch. It changes native files, so batch it into the next store build (`builds.md`). |
| 18 | iPad full screen | The layout works when iPadOS resizes the window; `UIRequiresFullScreen` is not relied on. If older iOS versions still need it, `UIRequiresFullScreenIgnoredStartingWithVersion` = 26 tells the system to ignore it from 26 on. A launch screen is present. | Apple TN3192: the key is deprecated since iPadOS 26; with the iOS 27 SDK it no longer stops resizing; from iOS and iPadOS 27 a launch screen is required for App Store submission. |
| 19 | Permissions against Data safety | Build the universal APK from the release AAB, run `aapt2 dump permissions <apk>`, and compare every permission (plugins add their own through the merged manifest) with the Play Data safety form and row 4. | A permission the form does not declare is a Play rejection, and a plugin can add one nobody chose. |
| 20 | iOS scroll inset of a remote shell | `ios.contentInset` is absent or `"never"` when the web pads with `env(safe-area-inset-*)` under `viewport-fit=cover`. On a device recording, the header sits at the same height at rest and scrolled. | `"automatic"` makes UIKit add the safe area as a scroll-view inset on top of the CSS padding: in Cash's TestFlight build (2026-11-10) the header sat about 56 pt (one status bar) lower at rest and jumped when the page scrolled, and a large-title screen showed its inline title at rest. Safari and an installed PWA never show it, so only the shell does. |
| 21 | Route fallbacks under the bars | Every `loading.tsx` (or Suspense fallback) of a screen inside the app shell reserves `--safe-top` + the header height. A tab switch to a dynamic route shows the shell, not a bare skeleton under the status bar. | Cash showed a header-less skeleton under the status bar for 1 to 1.5 s on every switch to its dynamic tab: the store build looked broken in the first seconds a reviewer sees. |
| 22 | Second origin (reviewer demo) on Android | Each `server.allowNavigation` origin that runs app screens gets Capacitor's bridge. Capacitor 8 on Android injects it only for the `server.url` origin (`Bridge.loadWebView`), so add it with `WebViewCompat.addDocumentStartJavaScript` for exactly that origin (reference: cash-next-app `DemoOriginBridge.java` and its unit test). The production page sends the reviewer there with `location.replace`, not `assign`. Check over the WebView DevTools socket that `Capacitor.isNativePlatform()` is true on that origin, and that Back on its first screen leaves the app. | Without it, reviewers see a plain web page with no native feature (Apple 4.2), and `assign` leaves the production lock in history, so Back returns them to it. iOS injects the bridge into every main frame, so iOS needs no change. |
| 23 | Device recording before submission | Before the review notes cite a recording, a real phone running the store build records every tab at rest and scrolled, a tab switch and one sheet. Read it frame by frame: `ffmpeg -i rec.mp4 -vf "fps=1,scale=384:-1,tile=8x2" sheet.png`, then measure header and bar positions. | Emulator and browser checks passed while the TestFlight build had the row 20 and 21 faults; Nadav's own recording found them. |
| 24 | No plan price or upgrade ask on any route a link opens (3.1.1) | A bundled shell that ships the whole web app and claims every path (`applinks` `/*`, Android filters) reaches every route, not only the ones its menus link to. Sweep `src` for plan prices (`₪` with חודש, מנוי, ניסיון), trial or subscribe buttons, upgrade, renew and "write to us to continue" asks, and sign-up, pricing or sales links, including the marketing header and footer of any framed page. On native, each such route redirects home, and each such sentence sits in a web-only wrapper. Pin it with a test that finds the pages itself (by the price fields they read) and checks each ask's own branch, seen red on a removed and on an inverted gate. | MediZen 1.2, 2026-11-11: six review rounds found asks in turn on 5 screens, then the suspended page, the `/data-deletion` marketing frame, `/manage-professions`, `/profession-setup` and `/manage-subscriptions`; a fixed list and a line-window guard each missed the next one. |
| 25 | R8 keeps line numbers | With `minifyEnabled true`, `android/app/proguard-rules.pro` carries `-keepattributes SourceFile,LineNumberTable` and `-renamesourcefileattribute SourceFile` (Android's template ships both commented out). The AAB's mapping lets Play rename frames back, but without these lines every frame of a crash or ANR reads `Unknown Source`, with no line to fix. Check: `unzip -p app-release.aab BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map \| head -1` is present, and the rules file has both lines. Neither costs Play's obfuscation measure. |
