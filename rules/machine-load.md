# Machine load

Nadav works on the same machines the agents use, and many sessions run at once. Before heavy or repeated local work (test databases, replays, builds, browser runs, parallel agents), choose the setup that loads the computer least while keeping full quality and the fastest wall clock. Load is not a reason to skip a test, a review or a check.

- Use the smallest component the check needs: plain Postgres instead of a full Supabase stack when only SQL runs; one long-lived server with a pre-migrated template database cloned per test (`createdb -T`) instead of a fresh stack per run; one shared build or browser instead of one per agent. Every test still starts from a clean clone, not from a database another test wrote to.
- Heavy jobs go through `heavy-slot --` and databases through `pg-pool get <repo>` (`ci-policy.md`); cap concurrent stacks and replays, and tear each one down when its run ends.
- Wait by blocking (`docker wait`, `pg_isready -t`, `flock`, or a 2-5 s sleep loop of bash builtins), not by fast polling, and do not poll CI or a Claude task output at all (`ci-policy.md` rule 5).
- Throwaway test Postgres runs with `-c fsync=off -c synchronous_commit=off -c full_page_writes=off` or a tmpfs data dir, because its flushes queue behind every other write on the disk. Real or shared data never runs that way.
- A throwaway container from an image that declares a volume (every `postgres` image) starts with `--rm` or with `--tmpfs` on its data dir, or is removed with `docker rm -fv`. Plain `docker rm -f` leaves the anonymous data volume behind.
- Playwright configs and scripts launch Chromium with `ignoreDefaultArgs: ['--disable-dev-shm-usage']` (in `use.launchOptions` or in `chromium.launch()`); add it when you touch a config that lacks it. Playwright passes `--disable-dev-shm-usage` by default, and with that flag Chromium keeps its shared memory in `/tmp` on disk instead of `/dev/shm` in RAM, which has frozen the desktop. Claude Code's Playwright MCP already gets the fix through `PLAYWRIGHT_MCP_CONFIG` (set by `update.sh`); the Codex and Grok Playwright MCPs do not.
- An extra server is fine when it is the lighter path (a staging database, a container on another machine, a cloud instance), as long as it holds no real customer data. Anything that costs money goes through the money gate.
- When Nadav lifts the cap on the number of agents, say the live load once and keep browser and database work in `heavy-slot` and `pg-pool`: his override is for the agent count, not for the queues.
- Measure before and after (load average, container count, run time) and say what the choice saved.
