# `rm` targets: literal absolute paths

Claude Code checks every `rm` and `rmdir` before it runs. It stops one whose target could turn out to be `/`, the home directory, the working directory or a top-level directory, and any command it cannot read well enough to rule that out. In bypass mode a hook (`rm-prompt-answer.sh`) answers that prompt at once with a denial and the rewrite, so the session does not stand still for two minutes (Nadav, 2026-11-14, asked that these stops end; measured that day at 0.2 to 0.4 s, also inside Orca). The check itself stays on. Its off switch, `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS`, has no effect while any permission hook is installed, and Orca installs one in every profile; Anthropic documents the switch for isolated machines only.

- Write each removal target as a literal absolute path below the directory you mean (`rm -rf /home/nadavcohen/project/tmp/x`). The check stops a path rooted at `$HOME` or `~` (`"$HOME/${rel:?}"` too), a variable set from `$(pwd)` or a similar command, a target that is a command substitution, and some globs (`logs/*/*`). A variable that holds a path you wrote passes when it is guarded: `rm -rf "${T:?}"/*`.
- When the path has to be computed, run the command that computes it on its own first, read what it prints, and remove that literal path in a second command. A removal is not moved into a script file, `eval` or another wrapper to get around the check: nothing checks it there.
- The check also stops a command it cannot parse. Write file contents with the Write tool, not with a heredoc that more commands follow (`&&`, `;`, lines after `EOF`), and keep text that only mentions `rm` and removes nothing (test cases, a commit message) in a file (`bash <file>`, `git commit -F file`).
