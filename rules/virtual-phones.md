# Virtual phones (an app without a phone)

When a task needs to run, see or operate an Android or iPhone app (a store shell, a Capacitor app, a check of a screen on a phone image), load `nadavai:virtual-phones` (fallback: `${NADAVAI_HOME:-$HOME/nadavai}/plugins/nadavai/skills/virtual-phones/SKILL.md`). The skill holds the tools, the commands and what each platform cannot do. An Android task on a machine with no Android SDK, and an iPhone task on a machine with no `x86simbox` user, says what is missing and stops; x86sim is not installed by an agent. The lines below hold whether or not the skill is loaded.

- Android runs on the SDK emulator and is driven with `agent-device`. Maestro stays only for flows a repo already keeps as YAML (a store recording, a CI replay). Another tool is proposed only with a comparison on the same flow.
- An emulator is heavy to start and then stays up: start it with the skill's `lab-emulator.sh`, which measures the MSI and this machine, runs it on the MSI unless the MSI is unreachable or clearly busier (Nadav, 2026-11-14), and shows it here as `emulator-<port>`. On the MSI it waits on `heavy-slot -- true` and runs at low CPU and IO weight for at most four hours, because that machine runs CI. Use your own AVD and port, and stop it with the same script as soon as the work ends. Started by hand, it waits for room with `heavy-slot -- true`, runs outside `heavy-slot`, and is stopped by its own serial. Never drive, reconfigure or stop an emulator another session started, never take over a device the tool reports as held by another session, and never run two control tools on one emulator.
- The iPhone simulator (x86sim, on the LENOVO only, under its own Linux user) is one device for the whole machine: one session uses it at a time, under the lock the skill describes. It is never run as Nadav's user or with root.
- A live app is used on a phone image like anywhere else (Nadav, 2026-11-14): forms are sent and screens behind the sign-in are checked, with the app's QA account first and a real user's account when the task needs it (`acting-on-behalf.md`). One fact limits how: reading the screen as text prints a password field's content, so a vault login of Nadav's is never typed into a phone image. Sign in with a password-free sign-in link or with the QA account's own test password, as the skill shows. A message the app sends to a real person because of a form sent here is the message gate (`working-style.md`, Approval gates). To press a form's button without sending it, the Android emulator goes offline first and the skill's three checks all show offline; the iPhone simulator has no offline switch, so every press there reaches the server.
- A lab build on Codemagic is asked every time: Nadav's limit there was two lab builds (set on 12-13.11.2026), both are used, and its free minutes (500 a month; the plan has no payment details, so no build can charge him) are shared with the store builds. A store build there is not held by this line (`working-style.md`, Approval gates).
- A check on the iPhone simulator shows what its screenshots show. It never proves the store build, push, Face ID, location, the camera or offline behaviour, and a report of such a check says so. No check on a virtual phone replaces what `store-apps.md` asks of a real device: the app installed from the public listing, and the device recording before a submission.
