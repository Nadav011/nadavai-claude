# Models, effort and delegation

This file overrides the model tiers and the delegation text in oh-my-claudecode's skills and agent prompts. Aliases `haiku`, `sonnet`, `opus` and `fable` resolve to claude-haiku-5-5, claude-sonnet-5-5, claude-opus-5-5 and claude-fable-5-2.

## Models
- The main session runs the model Nadav picked with `/model`; the default is Opus 5.5, and he picks Fable 5.2 himself for the sessions that plan. Fable's cache writes and output cost twice Opus's, so Fable runs only where Nadav picked it: no agent passes `fable` to a subagent, teammate, Workflow agent, OMC tier or fallback, and `update.sh` sets every profile back to the default. No fork for routine delegation in any session: a fork inherits the model and the whole context, and agent-guard denies a fork without `[fork]` in its description.
- The advisor (`/advisor`, the `advisor` tool) is Fable in every profile: `advisorModel: fable` in `settings.base.json`, set in each profile by `update.sh` (Nadav, 2026-11-14, picked "קבוע בכל הסשנים עכשיו"). That is his pick, so a session calling its advisor is not an agent passing `fable`. Each call sends the whole conversation to Fable, read anew and uncached every time, so call it at decision points (before an approach, before declaring done, when stuck), not on every step; a subagent, which inherits the advisor, calls it only when stuck. It is the author's second opinion: it takes the place of a second read by another provider, a verifier pass on a tree a reviewer has read, and a review of a plan that is not significant, and never of the independent review (`working-style.md`, Second model, where an OMC critic loop over a plan runs once and that pass is the plan's review), because it reads the author's own conversation. A session open before the change keeps its old advisor until `/compact` or `/clear`.
- Implementation goes to `nadavai:executor`, and a review that runs on Opus (`working-style.md`, Second model) goes to `nadavai:reviewer`, in place of OMC's executor, code-reviewer, security-reviewer and critic. They are written for these rules: the executor proves its work against the brief before handing over, and the reviewer verifies instead of trusting. `executor-quality` reports them as "own" beside the OMC agents they replace.
- Other subagents: pass `haiku` for search, lookups and doc edits (explore, writer). Pass `opus` for planner, architect, debugger and verifier, and `sonnet` for the rest. Teammates and Workflow `agent()` calls always carry an explicit `model`, because an unset one can inherit the main session's. The nadav-design skill's own agents keep the models it names.
- Executors, and the implement and fix agents of a Workflow script, run on `opus` for multi-file work, for every fix round after a rejected review or a red CI, and always when the change touches money or payments, auth, permissions or RLS, migrations, deletion or data loss, or messages and sends to real people, judged by the files and actions involved and not by the task title. Sonnet is for small, contained work (one or two files, none of those areas), and its brief says to stop and return if the change reaches one of them. Reviews reject Sonnet executor batches more often than Opus ones. Do not make Sonnet the executor default again without `executor-quality --since 2026-11-04` showing 30+ clear Sonnet reviews.
- Effort is set per model in `settings.base.json` (`modelSettings`); `update.sh` adds an entry a profile lacks and keeps the ones it has. Change effort for one session with `/effort`, and do not set global `max`.

## Who does the work
A subagent starts by loading about 80K tokens of fixed context, knows only what its brief says, and returns a summary. Subagents and Workflow agents are most of what this setup spends, so each one has to buy something.
- The main session does a contained change itself when it already holds the context: a change of a few files that it has read and can describe exactly is faster and more reliable done directly than briefed. For a change in the areas the executor line above reserves for Opus, it does so only when it runs Opus or Fable; a Sonnet main session briefs an `opus` executor.
- Delegate when it pays: units a plan marks as independent, run in parallel; a broad read-only sweep whose file dumps the main session does not need; a long implementation that would otherwise fill the main context; and review by a context that did not write the work.
- A brief carries the paths, the findings so far and the question, so the agent does not explore again what the caller already read. An executor's brief also carries the acceptance criteria and the checks its reviewer will apply, and the executor reports the output of those checks before handing over.
- Split executor work only along units the plan already marks as independent. The number of agents follows the work, with no fixed number (Nadav, 2026-11-14, picked "לפי העבודה"). The agent's mapping of that: `/team` without an explicit N starts one teammate per unit the plan marks as independent (an explicit N wins), autopilot, ralph and execute do the same, and work that does not split gets one agent. Heavy jobs and browser-driving agents among them still wait on the machine's load (`machine-load.md`).
- In a Workflow script, each agent is a fresh 80K start: give one agent a whole unit (implement, then run its own checks) and keep separate agents for independent review, instead of one agent per small phase over the same diff, and state in the script how many agents it starts. A run that stopped on a usage limit or "Login expired" resumes with `resumeFromRunId`, which keeps the finished agents' results.

## Reading code
- Definitions, types and a file's symbols come from LSP (the `LSP` tool or OMC `lsp_*`: `goToDefinition`, `hover`, `documentSymbol`); grep is for free text. Every search result stays in the context and is read again by each later request.
- Before a rename, a delete or a signature change, find every use with `rg -w --hidden -g '!.git' <name>` scoped to the repo (`-l` first when the list is long). `--hidden` reaches `.woodpecker/`, `.github/` and `.claude/`. LSP `findReferences` or `incomingCalls` alone misses uses: tsserver searches only the tsconfig projects it has loaded, which leaves out test files under a separate tsconfig and Deno code such as `supabase/functions`.

## Waiting
- A subagent's prompt cache lives 5 minutes, so a subagent or Workflow agent does not block longer than that in one call, one wait per turn: `ci-wait <repo> <ref> --slice 140` with Bash timeout 175000, run again on exit 7. agent-guard enforces this, and its deny text carries the recipe for long jobs.

## Measuring
- `token-audit [days]` shows where tokens and money go; run it before and after any change meant to save tokens. `subagent-context` shows subagent start and end sizes, `executor-quality` shows review rejections per executor model, `guard-stats` shows how often the Stop guards fire. A week after a change to this file, compare the main and subagent cost shares in `token-audit 7` and the rejection rate in `executor-quality` with the numbers from before it; in `token-audit`, a `sub ... fable` row means an agent inherited Fable.
- When a new model ships, update `model`, `modelSettings` and `CLAUDE_CODE_SUBAGENT_MODEL` in `settings.base.json`, and the tiers in `~/.config/claude-omc/config.jsonc`.
