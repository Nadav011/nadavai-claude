# Model routing (set 2026-10-11)

This file overrides the model tiers in the OMC block of ~/.claude/CLAUDE.md (for example verifier and code-reviewer always run on opus).

Aliases `haiku`, `sonnet`, `opus` resolve to claude-haiku-5-5, claude-sonnet-5-5, claude-opus-5-5.

- Fable is never used (main loop, subagent, teammate or fallback); enforced by `availableModels` in settings.base.json, which falls a Fable request back to an allowed model.
- Main loop: Sonnet 5.5 at xhigh, set by `/model` (global) and by `model` in settings.base.json. Move to Opus 5.5 for architecture, hard debugging and security work. Why: Opus burns the 5-hour quota several times faster.
- Subagents: leave `model` unset so they run on Sonnet 5.5 (`CLAUDE_CODE_SUBAGENT_MODEL`). Pass `haiku` for search, lookups and doc edits (explore, writer). Pass `opus` for planner, architect, critic, debugger, verifier, security-reviewer and code-reviewer. Why: a hard bug or a completion gate costs more when the model is weaker than it costs in quota; the volume is in executors and forks.
- Executors (and the implement/fix agents in a Workflow script): `opus` for complex or multi-file work, and always when the change touches money or payments, auth, permissions or RLS, migrations, deletion or data loss, or messages and sends to real people (judged by the files and actions involved, not by the task title), and for every fix round after a rejected review or a red CI. Sonnet only for small, contained work: one or two files, none of those areas; its brief says to stop and return if the change reaches one of them. Reviewers stay on Opus, and the nadav-design skill's own agents keep the models it names. Why: reviews rejected Sonnet executor batches far more often (measured 2026-11-04 with `executor-quality`; numbers in ~/.claude/projects/-home-nadavcohen/memory/token-economy-2026-11.md). Do not make Sonnet the executor default again without `executor-quality --since 2026-11-04` showing 30+ clear Sonnet reviews.
- Code lookup: definitions, types and a file's symbols through LSP (the `LSP` tool or OMC `lsp_*`: `goToDefinition`, `hover`, `documentSymbol`) before grep or reading whole files; grep for free text. Why: in the week to 2026-11-03, Bash search and cat/sed reads were 94% of Bash output (~450M chars), and every result is re-read by each later request in that context.
- Before a rename, a delete or a signature change, find every use with `rg -w --hidden -g '!.git' <name>` (scoped to the repo, `-l` first when the list is long; `--hidden` reaches `.woodpecker/`, `.github/` and `.claude/`), never with LSP `findReferences` or `incomingCalls` alone. Why: tsserver searches only the tsconfig projects it has loaded; on therapy-flow-v2 (2026-11-04) it returned 1 of 8 uses on the first call and 3 on the second, missed the test files (a separate `tsconfig.tests.json`), and no tsconfig there covers the 694 Deno files in `supabase/functions`.
- A subagent's brief carries the paths, the findings so far and the question, so it does not re-explore what the caller already read. An executor's brief also carries the acceptance criteria and the checks its reviewer will apply, and the executor reports those checks' output before handing over. Why: reviews rejected 46% of Opus executor batches (54/117, 2026-10-24 to 11-07); measure again with `executor-quality --since 2026-11-08`.
- Split executor work only along units a plan already marks as independent: each new agent starts at about 80K tokens and adds a review batch. Measure with `subagent-context`.
- A Workflow run that stopped on a usage limit or "Login expired" resumes with `resumeFromRunId`, never a fresh run. Why: 7.4% of workflow-agent cost (835M) went to agents that ended on a limit (14 days to 2026-11-05).
- A subagent or Workflow agent never blocks over ~5 minutes in one call, one wait per turn: `ci-wait <repo> <ref> --slice 140` with Bash timeout 175000, run again on exit 7.
  Enforced by agent-guard, whose deny text carries the full recipe (long jobs, waits over ~30 minutes). Why: a subagent's prompt cache lives 5 minutes.
- `token-audit [days]` measures where tokens go (by model, agent type, tool, cache-write cause). Run it before and after any change meant to save tokens.
- No forks for routine delegation: a fork inherits the parent model and its full context (~290K tokens per request).
- Effort: xhigh for Opus and Sonnet, never global max (it scores lower than xhigh on Sonnet 5.5's own benchmarks).
- A new model ships: update `CLAUDE_CODE_SUBAGENT_MODEL` and `modelSettings` in settings.base.json, and the tiers in `~/.config/claude-omc/config.jsonc` (outside this repo).
